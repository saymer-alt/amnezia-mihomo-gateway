# AGENTS.md — amnezia-mihomo-gateway

Постоянная инструкция для AI-агентов (в первую очередь ZCode), работающих с этим репозиторием.
Дополняет `README.md` и `install.md`, не дублирует их: README — документация пользователя
(схема, настройка TUN Mihomo, проверка, траблшутинг), здесь — правила работы и ловушки для
агента. Язык проекта и документации — русский. Владелец: `saymer-alt`, ветка `main`.

## Назначение

Однокомандный установщик (bash, root) для VPS: направляет трафик клиентов AmneziaWG
(Docker-контейнер `amnezia-awg`) через TUN-интерфейс Mihomo (Clash Meta) `tun-mihomo`, чтобы
клиенты выходили в интернет с IP Cloudflare WARP, а реальный IP VPS оставался скрытым.
Целевая среда: Debian 12 / Ubuntu 22.04+, systemd, Docker, установленный Mihomo
(`mihomo.service` либо docker-контейнер). Dev-хост владельца — Windows (Git Bash): скрипты
проекта выполняются ТОЛЬКО на целевом VPS, никогда на dev-хосте.

## Структура репозитория

| Путь | Роль |
|---|---|
| `install.sh` | Продукт. Инсталлятор v2.0, единственный источник истины: целевые скрипты и юниты генерируются его heredoc'ами |
| `uninstall.sh` | Полное удаление: systemd-юниты, `/usr/local/sbin/*`, sysctl-файл, правила iptables/ip rule (через `cleanup`) |

| `scripts/` | Справочные шаблоны сгенерированных скриптов с плейсхолдерами `<DOCKER_SUBNET>`, `<WG_PORT>`, `<HOST_INTERFACE>`; НЕ запускаются и отстают от install.sh (см. «Известные несоответствия») |

Нет CI, тестов, системы сборки, `.github`, менеджера зависимостей — и не нужно: это два

## Стек и доступные проверки

- `install.sh` / `uninstall.sh` — bash (используются bash-измы: `[[`, `EUID`, цветовые коды).
- Генерируемые скрипты — строго POSIX `/bin/sh` (dash на Debian/Ubuntu).
- Локально (Git Bash на dev-хосте) доступен только синтаксис-контроль:
  `bash -n install.sh && bash -n uninstall.sh` и `sh -n scripts/*.sh`.
  `shellcheck` — если установлен; проект под него не вылизан, замечания оценивать по существу.
- После изменений явно перечисли, какие проверки выполнены, а какие невозможны локально —
  всё, что требует живого VPS (прогон установщика, `ip rule`, iptables, спидтест с клиента),
  локально проверить нельзя.

## Что install.sh делает на целевом сервере (по порядку)

1. Проверки root/docker, затем fail-fast автоопределение (`set -e` + явные `exit 1`):
   контейнер по `name=amnezia-awg` (первый), docker-сеть (предпочитает имя с `amnezia`),
   подсеть, UDP-порт WG (`docker port`, fallback `docker inspect`), default-интерфейс.
2. `/etc/sysctl.d/99-amnezia-mihomo.conf`: `rp_filter=0` (обязательно для gvisor); BBR+fq
   добавляются ТОЛЬКО если congestion control ещё не bbr; `ip_forward=1` только если выключен —
   существующий сетевой hardening не перетирается. Плюс живое обнуление rp_filter на всех
   интерфейсах.
3. Таблица `100 mihomo` в `/etc/iproute2/rt_tables` (если записи нет).
4. DNS: если активен systemd-resolved — отключает его, пишет `/etc/resolv.conf`
   (1.1.1.1 / 8.8.8.8) и ставит `chattr +i`.
5. `/etc/docker/daemon.json` (DNS = docker0) — пишет ТОЛЬКО если файла нет; существующий не
   трогает (перезапуск docker — только в этой ветке).
6. Автопатч конфига Mihomo: ищет `config.yaml` в `/etc/mihomo /opt/mihomo /root /home`
   (maxdepth 3), бэкап `.bak.<epoch>`, затем 10 правок sed/awk: `fake-ip-range: 198.18.0.0/16`,
   `inet4-address: 10.255.255.1/30`, `stack: gvisor`, `auto-route: false`, `mtu: 1420`,
   `gso: true`, `auto-detect-interface: true`, `find-process-mode: off`,
   `store-selected/store-fake-ip: false`, удаление `endpoint-independent-nat`. Каждая правка
   обрабатывает и «ключ есть» (sed), и «ключа нет» (awk-вставка) — сохраняй обе ветки.
7. Генерирует `/usr/local/sbin/warp-docker-routing.sh`: ждёт `tun-mihomo` до 30 секунд,
   поднимает `txqueuelen 5000`, затем маршруты (`default dev tun-mihomo table 100`;
   `fake-ip-range` через tun в main), затем правила (`from <docker-subnet> lookup 100 prio 100`;
   `fwmark 0x88 lookup main prio 40`), затем iptables (MARK ответов WG, `TCPMSS
   --clamp-mss-to-pmtu`, MASQUERADE, FORWARD ACCEPT позициями 1–2). Идемпотентность: старые
   правила удаляются перед добавлением, новые ставятся по схеме `-C || -A/-I`. Аргумент
   `cleanup` снимает всё.
8. Генерирует `/usr/local/sbin/check-warp-routing.sh` (watchdog) и три юнита:
   `warp-docker-routing.service` (oneshot + `RemainAfterExit`, `ExecStop=cleanup`),
   `check-warp-routing.service` + `.timer` (проверка раз в минуту, `OnBootSec=2min`).
9. Перезапускает Mihomo (systemd-сервис или docker-контейнер), `daemon-reload`,
   `enable --now` сервиса и таймера.

Повторный запуск install.sh идемпотентен: новый `.bak` конфига Mihomo, правила пересоздаются,
существующие значения sysctl/DNS не дублируются.

## Несущая логика (менять только с пониманием и решением владельца)

- **main-таблица не трогается**: весь policy routing живёт в таблице 100 — поэтому SSH сервера
  в безопасности.
- **`auto-route: false` в TUN Mihomo** — критично: при `true` Mihomo перехватит весь трафик
  сервера, SSH умрёт.
- **fwmark 0x88 + приоритет 40**: ответы WireGuard (UDP sport WG_PORT) обязаны уходить в main,
  минуя туннель — иначе handshake не завершится и клиенты не подключатся.
- **Приоритет 100 / таблица 100**: убрать правило — трафик клиентов уйдёт напрямую с реальным
  IP VPS (деанонимизация), а не просто «перестанет работать».
- **`rp_filter=0`**: при 1 ядро дропает асимметричные пакеты (docker bridge → tun).
- **Fail-secure**: при падении `tun-mihomo` fallback-маршрута нет — клиенты без интернета,
  но IP VPS не раскрывается. Watchdog чинит Mihomo/правила и НИКОГДА не должен добавлять
  прямой fallback-маршрут. Отдельный сценарий: `ExecStop=cleanup` снимает правила сознательно,
  трафик возвращается в main (прямой egress) — это задуманное поведение юнита, не авария.
- **`TCPMSS --clamp-mss-to-pmtu` + `mtu: 1420`**: двойная инкапсуляция AWG+WARP; по замерам
  владельца clamp даёт ~2x скорости. Не менять без новых замеров.
- **`inet4-address` на TUN обязателен**: без IPv4-адреса на интерфейсе MASQUERADE не работает.
- **IPv4-only**: IPv6 не маршрутизируется; при `::/0` в AWG возможна утечка по IPv6.

## Опасные зоны (способны отрезать SSH или сломать сервер)

- Любое правило, отправляющее трафик САМОГО сервера в `tun-mihomo` (`auto-route: true`,
  правила без привязки `from <docker-subnet>`, правки main-таблицы) — потеря SSH-доступа.
- Порядок применения: маршруты в таблицу 100 создаются ДО `ip rule add`; при обратном порядке
  трафик клиентов между шагами уходит в чёрную дыру. Удаление старых правил перед добавлением
  новых — тоже часть порядка, а не «лишний код».
- `resolv.conf`, systemd-resolved, `/etc/docker/daemon.json` — общесистемное состояние, не
  принадлежащее проекту; текущее поведение («только если отсутствует/активно») сохранять.
- FORWARD ACCEPT вставляется позициями 1–2 и обходит UFW DROP по умолчанию — намеренно.
- Watchdog раз в минуту перезапускает Mihomo при отсутствии `tun-mihomo` и перезапускает
  `warp-docker-routing.service` при слетевших правилах — изменения этого цикла проверять на
  петли перезапусков.
- Не унифицировать сценарии «сервис остановлен» и «упал tun-mihomo» — у них разный эффект
  (прямой egress vs чёрная дыра).

## Правила работы агента

1. Прежде чем менять существующее поведение — пойми, зачем оно сделано (комментарий в шапке
   install.sh и README фиксируют измеренные результаты), и проверь идемпотентность повторной
   установки на уже развёрнутом сервере.
2. Не удаляй и не переписывай рабочую функциональность ради «упрощения» кода — только по
   явной задаче владельца.
3. Значения окружения (подсеть, WG_PORT, интерфейс, 198.18.0.0/16, 10.255.255.1/30, таблица
   100, fwmark 0x88, приоритеты 100/40, mtu 1420) не менять без понимания назначения; в
   heredoc'ах они подставляются из автоопределения — не хардкодить.
4. Auto-detection fail-fast: не смог определить контейнер/подсеть/порт — скрипт прерывается.
   Не заменять прерывание догадками или дефолтами.
5. Перед существенными изменениями перечитать README.md (разделы «Настройка Mihomo»,
   «Траблшутинг»), соответствующие heredoc'и и шаблоны. Изменения поведения вносить в
   install.sh — он источник истины.
6. После изменений: `bash -n` обоих корневых скриптов, при наличии — `shellcheck`; явно
   сообщить, какие проверки выполнены, а какие возможны только на VPS.
7. Неоднозначная задача — сначала исследование репозитория и формулировка найденных
   ограничений, затем вопрос владельцу; не делать предположений.
8. Push в `main` делает установщик сразу доступным по curl (README/install.md ссылаются на
   `raw.githubusercontent.com/.../main/install.sh`) — коммит в `main` = релиз.

## Известные несоответствия (не «чинить» молча)

- `scripts/warp-docker-routing.sh` отстал от install.sh: коммиты 8eb641d и cc3ae73 (2026-07-29)
  меняли только install.sh, а шаблоны — снимок 2026-07-27. В шаблоне нет FAKE_IP_RANGE-маршрута,
  ожидания интерфейса (30 с), `txqueuelen 5000` и logger-сообщений. Синхронизация шаблонов —
  отдельное решение владельца, не «мелкий фикс».
- Примеры TUN-конфига в README расходятся с тем, что реально ставит install.sh:
  в README `inet4-address: 198.18.0.1/30` и `fake-ip-range: 240.0.0.1/4`, установщик пишет
  `10.255.255.1/30` и `198.18.0.0/16`.
- `install.md` озаглавлен старым именем «awg-warp-router».
- `uninstall.sh` пишет «сервер вернулся к стандартным настройкам», но фактически НЕ
  восстанавливает systemd-resolved, оставляет `/etc/resolv.conf` с атрибутом `+i` и запись
  `100 mihomo` в `/etc/iproute2/rt_tables`. Документировать поведение можно; менять — только
  с владельцем.
